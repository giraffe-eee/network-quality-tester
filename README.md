# 网络质量检测器客户端

Windows 桌面客户端针对竞技网游的实时链路质量设计，默认端点为 `47.102.44.115`。3.0 协议会在同一个测试窗口内并行执行 UDP 与 TCP：UDP 同时包含游戏实时包和背景压力包，TCP 用于观察可靠回显在 UDP 负载下的稳定性。

## 为什么更贴近实际游戏

传统网络测试通常把平均延迟、瞬时抖动和峰值速率分开显示。它们能够说明链路是否可用，却很难揭示游戏过程中真正影响操作的短时拥塞、无线重传和回包空档。

本检测器在一个连续窗口内同时模拟 `120pps` 游戏 UDP 包、周期性 `1KB` 事件包、约 `3Mbps/方向` 的完整 UDP 回显负载和并行 TCP 回显。评分不仅看平均值，还会计算连续丢包、最长 ACK 空档、P95/P99 尾延迟、压力下的有效双向吞吐和抖动突刺。因此，只有在负载下仍能稳定传输的链路才能获得高分，更适合评估竞技网游中的实际体验。

## 测试负载

| 模式 | 总时长 | UDP 负载 | 估计双向流量 |
| --- | ---: | --- | ---: |
| 快速 | 30 秒 | 120pps 游戏包 + 约 3Mbps/方向压力 | 约 25MB |
| 正常（默认） | 60 秒 | 120pps 游戏包 + 约 3Mbps/方向压力 | 约 50MB |
| 严格 | 120 秒 | 120pps 游戏包 + 约 3Mbps/方向压力 | 约 100MB |

游戏实时包的常规载荷在 `40-300B` 之间，每 24 个包插入一个 `1KB` 事件包。背景压力包补足 UDP 载荷速率，服务端回显完整载荷，因此上行和下行都会被实际占用。流量估算含 UDP 和 TCP 测试载荷，不含运营商计费误差；移动热点下应按需要选择模式。

模式时长是完整测试的实际时长，不是 UDP 阶段和 TCP 阶段相加。

## 评分标准

| 项目 | 分值 | 判定方式 |
| --- | ---: | --- |
| UDP 连续性与压力容量 | 40 | 游戏包丢包、连续丢包、回包空档占 35%；3Mbps 压力包丢包、P95/P99、回包空档和双向达标率占 65%。 |
| UDP 抖动 | 20 | 游戏包与压力包的持续抖动 P50、突发抖动 P95 共同计算。 |
| UDP 延迟 | 10 | 游戏包与压力包的中位 RTT、P95 RTT、P99 RTT 共同计算。 |
| TCP 稳定性 | 12 | 回显丢失、长回包空档、连续异常段和 P99 延迟共同判定。连接失败时为 0。 |
| TCP 抖动 | 8 | 持续抖动 P50 占 40%，突发抖动 P95 占 60%。 |
| TCP 延迟 | 10 | `0.35 x 中位 RTT + 0.50 x P95 RTT + 0.15 x P99 RTT`。 |

UDP 占 70 分，TCP 占 30 分。所有曲线采用连续插值，不会在某个临界值突然跳分。压力包的评分门槛比空闲探测更严格：出现少量压力丢包、回包空档、P95/P99 尾延迟或双向吞吐未达标时，都会明显拉低分数。高分不仅要求空闲时延低，还要求在约 3Mbps 每方向的持续 UDP 回显下保持吞吐、低丢包和低尾部延迟。

作为回归校准：干净的重度有线样本约为 98 分；无线链路若游戏包丢包约 `0.5%`、压力包丢包约 `1.2%`、压力 P95 RTT 约 `220ms`、双向吞吐约 `2.65-2.8Mbps`，评分约为 `53`。实际分数由测试窗口内的真实表现决定，稳定的 120 秒窗口不会被人为压低。

2.x 的小包报告没有压力包、双向吞吐和压力延迟字段，不能与 3.0 重度负载分数直接横向比较。

分数衡量的是客户端到检测端点的整条路径，而不是服务器单独的网络质量。云服务器网络良好，只能说明服务端出口正常，不能抵消本地 Wi-Fi、移动基站切换或运营商链路造成的波动。

## 本地运行

```powershell
./bootstrap.ps1
.\.venv\Scripts\python.exe app.py
```

命令行验证：

```powershell
.\.venv\Scripts\python.exe app.py --headless --server 47.102.44.115 --duration 30 --rate 120 --target-mbps 3
```

## 打包 exe

```powershell
./build.ps1
```

成品位于 `dist/网络质量检测器.exe`。首次构建会下载 PyInstaller。

客户端目录中的 `tcl-runtime/` 是 exe 自带图形界面所需的 Tcl/Tk 运行时，发布时不要删除。

## 发布到 GitHub

本机已登录 GitHub CLI 时，构建后执行：

```powershell
./publish.ps1 -Version 1.1.0
```

脚本会向 `giraffe-eee/network-quality-tester` 创建或更新对应的 Release，并上传 exe 与 SHA-256 校验文件。可用 `-Repository owner/repo` 覆盖目标仓库。
